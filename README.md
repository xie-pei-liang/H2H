# H2H · 羽毛球球员交手记录

一个中文单页应用，用于展示和手动维护**一对羽毛球球员**的资料、胜场总览及比赛明细。页面包含展示区和可展开的操作区，适合记录个人整理的交手资料。

> 本说明依据 `main` 分支提交 [b689163](https://github.com/xie-pei-liang/H2H/commit/b689163ae66a0e394ba32b73357b56d20c2f0911) 中的代码整理。默认球员及胜场属于代码内置初始值，未附赛事数据来源，不能视为经过核验的实时统计。云端服务是否可用、访问权限及正式部署方式均**待确认**。

## 功能模块与已实现内容

| 模块 | 当前已实现 |
| --- | --- |
| 交手总览 | 展示左右两侧球员的姓名、国家/地区、头像和手动设置的胜场 |
| 球员与总比分编辑 | 点击“编辑数据”展开操作区，修改资料和胜场，点击“保存球员信息”保存 |
| 头像 | 支持图片 URL，或选择本地图片并通过 `FileReader.readAsDataURL` 转为 Data URL；选择图片后仍需保存球员信息 |
| 比赛明细 | 添加日期、赛事、轮次、胜者、比分、备注；新记录插在列表最前；支持删除和显示记录条数 |
| 本地持久化 | 将状态和同步配置分别以 JSON 保存到浏览器 `localStorage`，再次打开时读取 |
| 云同步客户端 | 保存同步配置、手动拉取、修改后整份上传、每 8 秒轮询拉取，并显示同步状态 |
| 页面布局 | 内嵌 CSS，包含窄屏适配；编辑区支持展开、收起 |

**统计口径：**“共 N 场交手”来自 `matches.length`；左右胜场来自独立的 `scores` 字段。添加或删除比赛**不会**自动增减胜场，需要手动维护。初始状态为石宇奇 / 周天成、胜场 11 / 7、比赛列表为空，因此两种计数可以不同。


## 运行方式

### 直接打开

1. 克隆仓库，或下载并解压仓库文件。
2. 用现代浏览器打开 `index.html`。
3. 点击“编辑数据”，修改球员信息或添加比赛并保存。

克隆命令（需要自行安装 Git；也可直接下载 ZIP）：

```sh
git clone https://github.com/xie-pei-liang/H2H.git
cd H2H
```

当前前端使用原生 HTML、CSS 和 JavaScript，未引用外部脚本、样式库或 Firebase SDK，无需 `npm install` 或构建步骤。浏览器需要支持 `localStorage`、`fetch`、`FileReader` 及代码使用的现代 JavaScript 语法；最低浏览器版本**待确认**。

**首次打开会自动尝试云同步，不能将“直接打开”理解为默认只在本地保存。** 需要避免访问云端时，可先断网查看页面；当前没有可靠、持久的“关闭同步”开关。外部头像链接和云同步需要网络。

通过 `file://` 打开时，本地存储及跨域请求行为可能受浏览器限制。若遇到问题，可选择本地静态 HTTP 服务。

### 可选：本地静态服务

若已安装 Python 3，在仓库目录运行：

```sh
python -m http.server 8000 --bind 127.0.0.1
```

然后打开 [本地页面](http://127.0.0.1:8000/)。这是可选开发方式，Python 不是应用运行依赖，也不是仓库已有的后端。

本地文件、不同端口、不同域名或不同浏览器使用的存储可能不同。发送 `index.html` 给他人不会把当前浏览器中的数据打包进去；但若双方连接同一云端地址和房间，仍可能读取同一份云端数据。

### 部署状态

页面具备由静态服务器提供的文件形态；仓库未包含部署脚本、CI 工作流或托管配置。是否已启用 GitHub Pages、线上访问地址、托管平台及发布流程均**待确认**，此处不提供未经确认的线上地址。

## 数据存储

### 本地存储与数据结构

| localStorage 键 | 内容 |
| --- | --- |
| `badminton-h2h-state-v2` | 球员、总胜场和比赛数组 |
| `badminton-h2h-sync-v1` | 同步配置 `{ url, room }` |

状态结构示例（对应内置初始值）：

```json
{
  "players": {
    "left": { "name": "石宇奇", "country": "中国", "avatar": "" },
    "right": { "name": "周天成", "country": "中国台北", "avatar": "" }
  },
  "scores": { "leftWins": 11, "rightWins": 7 },
  "matches": []
}
```

每条比赛记录包含 `id`、`date`、`event`、`round`、`winner`、`score`、`note`；`winner` 存储 `left` 或 `right`，渲染时显示对应球员的当前姓名。比赛列表按添加顺序倒序展示，不按比赛日期自动排序。

代码会整理输入字段，例如将胜场解析为非负整数、为未填写的赛事使用“未命名赛事”，并在本地状态解析出错时回退到初始状态。这些处理不等于完整的数据校验；日期和比分仍是自由文本。

选择的本地头像以 Data URL 随状态保存，并随整份状态上传云端，没有单独的图片存储服务。较大的图片可能占满浏览器存储或增大传输量；当前没有压缩、大小限制或存储配额错误处理。

清除浏览器站点数据会移除本地状态和配置；若云同步仍启用，之后打开页面还可能从云端恢复或覆盖本地数据。当前没有导入、导出或备份恢复界面。

## 云同步机制

### 已确认的客户端实现

默认配置写在 `DEFAULT_SYNC_CONFIG` 中：

- 同步地址：`https://h2h-badminton-default-rtdb.asia-southeast1.firebasedatabase.app`
- 房间：`H2H`
- 轮询间隔：`8000` 毫秒

客户端使用 `fetch` 访问 Firebase Realtime Database 风格的 REST 接口，没有引入 Firebase SDK。接口由“去掉末尾斜杠的地址 + / + URL 编码的房间名 + .json”构成，例如默认路径为 `/H2H.json`。

| 时机 | 行为 |
| --- | --- |
| 页面初始化 | 先读取并渲染本地状态；配置有地址时立即尝试 `GET` 拉取 |
| 拉取到非空数据 | 整份替换内存状态，写入本地存储并重绘页面 |
| 拉取结果为空值（如 `null`） | 尝试将当前状态整份上传 |
| 保存资料、添加或删除比赛 | 先保存本地状态，再通过 `PUT` 上传整份状态到当前房间 |
| 点击“保存同步设置” | 更新内存配置并保存本地配置，然后立即拉取；远端已有数据时会覆盖本地状态 |
| 点击“从云端拉取” | 使用当前已保存的内存配置拉取；仅修改输入框不会切换同步目标 |
| 定时同步 | 每 8 秒拉取；焦点位于操作区内部时跳过本次轮询；这不会阻止启动拉取、手动拉取或此前已发出的请求 |

多台设备使用相同地址和房间时指向同一份远端状态。房间名只是数据路径，代码没有将其实现为密码或访问控制。

### 服务与配置待确认事项

- 内置地址指向的实际服务是否仍可用、归属及维护方式：**待确认**。
- 数据库安全规则、读写权限、认证要求、配额、备份和跨域访问配置：**待确认**。仓库没有相应配置文件或后端实现。
- 自建兼容后端的具体实现与部署流程：**待确认**；仅填写地址不能证明服务已就绪。客户端预期 `GET` 返回整份状态或 `null`，`PUT` 接收整份 JSON 状态，并检查 HTTP 状态码。
- 前端请求未携带显式认证令牌，也没有登录界面；不能据此断言实际数据库允许匿名访问，更不应据此开放数据库读写权限。

### 当前同步限制

- **默认自动连接：**没有保存过配置时也会使用内置地址及 `H2H` 房间，不是默认关闭。
- **清空地址无法永久关闭：**当次保存空地址会让内存中的同步停止，但保存到本地的配置会回填默认地址，刷新后再次启用；已有轮询计时器也没有显式清理。
- **地址归一化不一致：**持久化配置时，空地址或任何包含 `firebaseio.com` 的地址会被替换为内置默认地址；点击保存后的当次内存配置却保留原始输入，刷新前后可能连接不同地址。页面的 `firebaseio.com` 示例占位符与此逻辑存在冲突。
- **整份覆盖：**没有版本号、时间戳、冲突检测或字段级合并。并发写入可能互相覆盖，轮询也可能用远端旧数据覆盖尚未同步的本地修改。
- **失败恢复有限：**没有离线上传队列、自动重试上传或请求顺序控制。轮询拉取失败时不会显示错误；拉取为空后即使内部上传失败，外层仍可能显示“已上传当前数据”，因此状态文案不能作为服务可用性的充分证据。

## 其他已知限制

- 只维护一对球员，没有多组对阵管理、球员库、搜索、筛选或分页。
- 比赛支持添加和删除，尚无单条编辑、撤销删除或删除确认；删除按钮位于展示表格中，收起编辑区不会禁止删除。
- 没有自动获取赛事数据、核验数据来源或依据比赛明细自动统计胜场。
- 没有严格的日期、比分、头像 URL 或远端 JSON 结构校验；部分异常数据仍可能导致运行错误。
- 云端拉取重绘会重填编辑表单，未提交的输入可能被覆盖；焦点跳过轮询只提供有限保护。
- 仓库尚无自动化测试、贡献指南、Issue / PR 模板或许可证文件；许可证与使用授权范围**待确认**。
